# Frozen preparation, extraction and annotation rules

Use exactly the six selected task/source slots and six byte-verified local PDFs.
Reserve all groups in development-exposures.json before preparation. Independently
assert their original seed-17 group assignments remain development; reservations
must not recruit internal-final groups. Keep selected order separate from the
existing task-hash preparation order recorded in selection.json.

## Preparation and native extraction

Hash-bind this plan, script, runtime, release bytes/source manifest, selection,
acquisition result and all six originals, exposure registry and reference-issue
registry before execution. Filter raw release rows to exactly the six selected IDs
before adaptation. Apply the existing identity-bound issue registry without changing
answers. Use existing full_agent input projection and seed17 preparation; this does
not authorize or enable paid full-agent inference. Persist all prepared files and
complete selected denominator. Keep source/review labels out of extraction inputs.

Ingest each local original through the existing pypdf-layout extractor and v2 PDF
diagnostics. No network, OCR, font substitution, text repair, parser change or
source replacement. Preserve per-source pending/completed/failed dispositions and
partial artifacts. Attempt every selected source once after ordinary extraction
failure; interruption leaves remaining slots pending. If any source fails, retain
all six slots and report a blocked assessment stage, not zero retrieval coverage.
Assemble the six-source corpus/binding only if all six succeed. Recheck originals,
prepared files, extracted hashes and frozen inputs before reporting completion.

Report page/line counts, empty-native-text pages, warning counts, parser/package
versions and hashes only. Native extraction success is not financial-content
validation. The legacy source `complete` field means the ingestion finished; the
explicit extraction field `text_completeness: not_verified` governs quality claims.
Visual quality review occurs during annotation, not inferred from warning counts.

## Reference-aware, outcome-blind annotation

Before any retrieval or context results on this cohort are computed/inspected,
author complete evidence-component packets from the selected question, benchmark
reference claim/evidence and original pages. References are claims to verify, not
authoritative truth. Do not give annotators search rankings, returned snippets,
read retention or baseline/challenger results. The known policies remain fixed.

Initially inspect full referenced physical pages (zero-based evidence index +1),
with at most one adjacent page on either side when needed for headers, units,
qualifications or table continuation. Render those pages and compare native lines.
Record exact page scope and reasons. If this is insufficient, mark unresolved or
record a separately frozen scope expansion before any policy coverage is observed;
do not silently expand until a preferred metric passes.

For each case define all necessary source roles: entity/statement scope, requested
period and units, requested facts or calculation operands, and material qualifiers.
For qualitative questions include every requested comparison, causal claim and
qualification needed to support the answer. A formula supplied by the question is
not invented as a source-text requirement; record calculation assumptions separately.
Do not require irrelevant boilerplate solely to inflate completeness requirements.

Each alternative must independently contain every required role. Use exact
nonempty source-line spans and original/text hashes. Do not pool partial alternatives.
Keep unmapped/unresolved cases with explicit reasons in the all-six denominator;
report any mapped denominator separately. Contradictory/ambiguous references remain
flagged and unmodified; do not score them as validated financial answers.

Have an independent coding-agent reviewer inspect the packet against the same
allowed pages and question/reference, still without retrieval results. Resolve
annotation disagreements before freezing packet bytes. These annotations are not
human financial validation. Record reviewer scope, discrepancies and remaining
uncertainty. Do not tune packets after results are opened; later revisions require
new versioned diagnostics preserving the original result.

## Comparison gate

After packet freeze, separately freeze original-question declared-document search,
one exact ranked-parent read per selected hit (at most five), independent top1/3/5
context snapshots, unchanged 32K serialized-output-character budget, and the exact
baseline/earlier-optional-results-first challenger implementations. Verify actual
responses and replay before grading. Preserve failures, blocked projections and
all six task dispositions; no retries, substitutes or result-driven policy changes.
This plan authorizes preparation/extraction and subsequent outcome-blind annotation;
it does not itself authorize an unfrozen retrieval/context experiment.
