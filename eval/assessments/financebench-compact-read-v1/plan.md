# Frozen compact-read metadata assessment

This is a development diagnostic on the same six exposed FinanceBench cases, not
fresh validation. Preserve the reviewed packets and every original question,
declared document, source byte, read window, evidence line and context policy.
The sole experimental change is `read_extraction_version`: `full-v1` versus
`pdf-returned-pages-v1`. Production remains full metadata by default.

## Freeze and attribution

Before any cohort calls, freeze this wrapper/plan, current runtime, immutable
six-case `compare.py`, its referenced files and projector modules, original
protocol/run/grade/journals, prepared data, corpus binding and annotations.
Generate a new-runtime inner protocol using the unchanged comparison schema;
never rewrite the historical protocol or bypass a verifier. Both modes use the
same inner protocol because that schema does not encode read metadata mode.
The outer protocol and mode-specific container paths are authoritative for mode
attribution. Inner protocol identity alone must not be presented as authorizing
compact behavior.

Load a fresh comparison module per mode; replace only that module's `Sources`
constructor with a checked factory supplying the explicit mode, restoring it in
`finally`. Do not replace `_freeze`, runtime digests, the read executor, snapshots,
policies, shared source module or grader. The source factory may check actual
search responses against the verified full-mode response before reads dispatch;
it returns that unchanged actual response.

## Compatibility before compact collection

Persist pending mode statuses first. Each inner run persists all six case slots
before dispatch. Run current-runtime full mode, then require every journal byte
and every case/search/read/budget/snapshot to equal the historical run. Validate
the old and new protocol hashes and permit only that explicit top-level protocol
hash substitution. Stop on any difference, preserving the failed compatibility
attempt; compact mode must not start.

For compact mode require exact actual search-response equality before any read.
All six original questions and documents stay fixed, with at most five ranked
parent reads each. Compare compact/full record requests, statuses, evidence lines,
locations, locators and source identities. They must be identical. Only known v2
PDF extraction metadata may change: retained page records must equal the full
records for the actually returned physical pages; every global field must be
unchanged, and the projection descriptor must correctly identify mode, scope,
counts, full-object hash and manifest reference. Unknown/legacy metadata stays
identical. Read budgets may differ only in serialized response size. A violated
metadata-only contract invalidates the assessment; do not score a new read failure
as a valid treatment outcome or replace it with a successful slot.

Reuse the exact baseline and earlier-read projectors and 32,000 serialized
output-string-character budget at independent one/three/five-read prefixes. The
metadata modes necessarily produce different serialized canonical histories;
within each mode the two priority policies must still receive identical histories.
Preserve blocked snapshots, ordinary failed ranks and zero-hit cases.

## Replay, labels and reporting

Both original mode runs must finish before grading starts. Each unchanged inner
grade independently replays its complete mode run and journals before parsing its
packets. Full-mode grade must equal the historical grade after validating and
substituting only the new protocol and run hashes. Keep all-six and mapped
location denominators and semantic correctness explicitly unmeasured.

The wrapper performs both grades in one process: the second grade replays before
its own packet parsing, but the process has already seen first-grade labels.
This is per-condition data-flow isolation, not a process-wide unseen-label claim.
No labels enter source search, read requests, response projection or context
policies. Hash-only packet access during collection is allowed.

Report metadata-mode wins/losses/ties at each fixed priority and priority-policy
wins/losses/ties within each metadata mode. Separately report operational blocking,
read failures/truncation, actual collection and replay call counts, evidence
completeness and response sizes. Collection uses six searches/at most thirty reads
per mode; each mode's grade repeats those calls once for integrity verification.
No paid/model calls, query changes, retries or extra reads are authorized.

Recheck frozen inputs, exact mode directories, run/journal hashes and all written
grade artifacts before completion. Unexpected failure or interruption leaves an
aborted assessment with partial/pending mode and case records, not a successful
comparison. Preserve all failed attempts. Later changes require a new version.

The reference ambiguities, public-data exposure and cross-suite issuer limitations
of the original cohort remain attached. Compact diagnostics retain global warnings
and uncertainty, but do not guarantee universal context fit, repair retrieval gaps
or validate financial answers. This assessment alone does not authorize promotion
of either context-priority policy or full-agent benchmark inference.
